# GitHub 동기화 규칙

## 호출 경계

- GitHub API와 raw README 호출은 `scripts/sync-repositories.mjs`에서만 수행한다.
- 브라우저 번들, React 컴포넌트, `src/lib/`에서 GitHub API를 직접 호출하지 않는다.
- 동기화는 `npm run sync`로 실행하며, 생성 결과는 `generated/repositories.json`에만 기록한다.

## 인증과 공개 범위

- 소유자는 `GITHUB_OWNER` 환경 변수로 지정하며 기본값은 프로젝트의 공개 소유자다.
- 인증이 필요한 경우에만 `GITHUB_TOKEN`을 요청 헤더에 사용한다. 토큰 값은 코드, 생성 파일, 문서, 로그에 기록하지 않는다.
- 비공개 저장소는 수집·출력하지 않으며, `private === false`와 `visibility === 'public'`을 모두 확인한다.

## 수집과 오류 처리

- 저장소·브랜치 목록은 페이지당 100개 단위로 페이지네이션한다.
- 저장소별 언어, README, 브랜치 수집은 독립적으로 처리한다. 보조 데이터 실패는 해당 저장소의 경고로 남기고 카탈로그 생성은 계속한다.
- README는 기본 브랜치에서 정해진 대소문자 변형 파일명만 찾고, 404는 README 없음으로 처리한다.
- README는 바이트를 디코딩한 뒤 최대 32,000자로 제한한다.
- 저장소 상세 수집은 현재 5개 단위로 제한한다. 호출량 또는 병렬도 변경은 GitHub API 제한과 실패 처리에 미치는 영향을 검토한 뒤 문서화한다.

## 변경 전 점검

- API 버전 헤더, 수집 URL, 인증 방식, 공개 범위, 출력 스키마를 변경하면 `docs/data/catalog-data-rules.md`도 함께 검토한다.
- 동기화 동작 변경에는 관련 유틸리티와 테스트를 추가하거나 갱신한다.
