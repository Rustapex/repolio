# 저장소 메타데이터 유지보수 기록

## 배경

다크 모드에서 필터의 네이티브 선택 목록이 흰 배경과 밝은 글자로 표시되어 옵션을 읽기 어려웠다. 또한 GitHub API의 `updated_at`을 카드의 `수정` 날짜와 정렬 기준으로 사용해, 실제 마지막 커밋과 다른 날짜가 노출됐다.

`Rustapex/FrontProject`를 GitHub API로 확인한 결과는 다음과 같다.

| 항목 | 값 |
|---|---|
| `updated_at` | `2026-08-01T06:57:26Z` |
| `pushed_at` | `2026-02-25T16:42:45Z` |
| 기본 브랜치 | `main` |
| 실제 브랜치 | `HAESU`, `MINGYEONG`, `YUNSEONG`, `main`, `yeongseok`, `해수` |

따라서 2026년 8월 1일 표시는 Repolio의 배포 시각이 아니라 GitHub 저장소 메타데이터의 갱신 시각이었다. `updated_at`만으로는 해당 갱신을 일으킨 세부 이벤트를 확정할 수 없으므로, 코드 변경 시점을 나타내는 화면에는 사용하지 않는다.

6개 저장소의 README 미리보기는 UTF-16 인코딩 바이트를 UTF-8 텍스트로 바로 읽으면서 대체 문자와 NUL 문자가 섞여 표시됐다. 저장소 데이터에는 기본 브랜치 이름만 있었고 전체 브랜치 목록은 수집하지 않았다.

## 수정 내용

- 필터 선택 목록은 다크 테마에서 배경과 글자색을 명시해 운영체제 네이티브 팝업에서도 대비를 유지한다. 라이트 테마 값은 변경하지 않는다.
- 카드의 `수정` 날짜와 `최근 수정` 정렬은 `pushed_at`을 사용하고, 원본 `updated_at`은 데이터에 계속 보존한다.
- README 응답을 바이트로 읽은 뒤 UTF-8, UTF-16LE BOM, UTF-16BE BOM 및 NUL 패턴을 판별해 디코딩한다.
- GitHub Branches API를 페이지네이션으로 수집하고, 실패해도 `default_branch`를 `branches` 배열에 보존한다.

## 검증

- UTF-8 및 UTF-16LE README 디코딩 단위 테스트
- 기본 브랜치 보정 단위 테스트
- 전체 동기화 후 `FrontProject`의 `branches` 배열과 `pushedAt` 확인
- 라이트·다크 모드 필터와 README 카드 브라우저 확인
