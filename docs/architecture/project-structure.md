# 프로젝트 구조 규칙

## 책임 경계

| 경로 | 책임 | 두지 않는 것 |
| --- | --- | --- |
| `src/components/` | props 기반 UI와 접근 가능한 화면 표현 | 원격 API 호출, 전역 데이터 변환 |
| `src/hooks/` | 브라우저 API와 재사용 가능한 상태 동작 | 화면별 마크업 |
| `src/lib/` | 필터·정렬·그룹 결합·README 처리 같은 순수 변환 | React 상태와 DOM 조작 |
| `src/types/` | 저장소 카탈로그와 화면 필터의 공용 타입 | 런타임 데이터 생성 |
| `src/data/` | 사람이 관리하는 정적 입력 데이터 | 동기화 결과 |
| `src/styles/` | 토큰, 기본 스타일, 컴포넌트 스타일 | 컴포넌트별 인라인 디자인 시스템 |
| `scripts/` | Node 기반 수집·검증·생성 작업 | 브라우저 번들에 포함되는 코드 |
| `generated/` | 동기화가 생성한 읽기 전용 카탈로그 | 수동 편집 데이터 |
| `tests/` | 외부에서 관찰되는 동작 검증 | 운영용 스크립트 |

## 의존 규칙

- `App.tsx`는 카탈로그·그룹 데이터, 화면 수준 상태, 최상위 컴포넌트 조립을 담당한다.
- 컴포넌트는 `types`와 `lib`를 사용할 수 있지만, GitHub API나 생성 스크립트에 직접 의존하지 않는다.
- 데이터 변환은 JSX 안에 중복 구현하지 않고 `src/lib/`로 분리한다.
- 새 공용 데이터 필드나 필터 값은 `src/types/repository.ts`를 기준으로 정의하고, 생성 스크립트·변환 함수·화면을 함께 검토한다.
- `generated/repositories.json`은 `scripts/sync-repositories.mjs`가 만드는 산출물이다. 직접 수정하거나 UI 코드에서 다시 생성하지 않는다.

## 새 파일을 추가할 때

1. 기존 디렉터리의 책임으로 해결 가능한지 먼저 확인한다.
2. 기능 전용 컴포넌트는 `components/`, 재사용 가능한 브라우저 동작은 `hooks/`, 순수 로직은 `lib/`에 둔다.
3. 새 최상위 디렉터리나 서로 다른 계층 사이의 새 의존성이 필요하면 이 문서에 이유와 책임 경계를 갱신한다.
