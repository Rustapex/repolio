# 저장소 카드 그룹 시각 계층 구현 계획

## 1. 문서 목적

이 문서는 [계층형 저장소 그룹 계획](2026-08-12_hierarchical-repository-groups.md)의 데이터 구조, 필터, README 처리 계획을 대체하지 않는다. 해당 계획 중 저장소 카드의 그룹 영역을 **어떻게 시각적으로 연결해 보일지**를 구체화하는 보완 문서다.

## 2. 변경 배경

현재 카드는 상위 그룹 칩을 먼저 나열하고, 모든 하위 그룹을 하나의 `세부 그룹` 목록에 함께 표시한다. 따라서 예를 들어 `#React`가 `#프론트엔드`의 하위 그룹인지, 다른 상위 그룹의 하위 그룹인지 즉시 알기 어렵다. 또한 상위·하위 칩이 모두 같은 파란색 계열이라 구조적 관계도 약하게 보인다.

변경의 목표는 다음과 같다.

- 상위 그룹과 그 하위 그룹을 하나의 독립된 블록으로 묶어 소속 관계를 명확히 한다.
- 접힌 상태에서는 상위 그룹만 빠르게 훑고, 필요한 그룹만 펼친다.
- 색상과 배치를 함께 사용해 관계를 전달하되, 색상만으로 구분하지 않는다.
- 현재 카드의 저장소명, 설명, 메타데이터, 언어 비율, README 배치는 바꾸지 않는다.

## 4. 확정할 카드 동작

### 4.1 기본 상태와 펼침 단위

- 카드가 처음 표시될 때 모든 상위 그룹의 하위 목록은 접힌 상태다.
- 각 상위 그룹은 독립적으로 펼치고 접는다. 하나를 펼쳐도 다른 상위 그룹은 자동으로 접히지 않는다.
- 상위 그룹에 연결된 하위 그룹이 없으면 상위 그룹 필터 칩만 표시하고 펼침 제어와 개수는 표시하지 않는다.

### 4.2 클릭 동작

- 상위 그룹명 칩을 클릭하면 해당 상위 그룹으로 저장소 목록을 필터링한다.
- 펼침 제어 영역(화살표와 `세부 그룹 n개`)을 클릭하면 해당 상위 그룹의 하위 목록만 펼치거나 접는다.
- 하위 그룹 칩을 클릭하면 해당 하위 그룹으로 저장소 목록을 필터링한다.
- 상위 그룹 칩의 필터 동작과 펼침 제어의 상태 변경은 별도 버튼으로 구현하여, 한 번의 클릭이 두 동작을 동시에 수행하지 않게 한다.

## 5. 시각 구조

### 5.1 접힌 상태

상위 그룹마다 한 줄 또는 하나의 블록을 만든다. 블록 안에는 다음 순서로 표시한다.

1. 상위 그룹 필터 칩
2. 펼침 제어: 방향 아이콘과 `세부 그룹 n개`

하위 칩은 접힌 상태에서 렌더링 공간을 차지하지 않는다. 사용자는 상위 칩과 개수를 보고 필요한 범위만 펼칠 수 있다.

### 5.2 펼친 상태

펼친 상위 그룹은 상위 그룹 칩과 펼침 제어 바로 아래에 전용 하위 그룹 컨테이너를 표시한다. 이 컨테이너에는 **해당 상위 그룹에 속한 하위 그룹만** 넣는다. 서로 다른 상위 그룹의 하위 칩을 하나의 공통 목록에 섞지 않는다.

상위 그룹명, 개수 표기, 하위 컨테이너의 순서와 경계가 색상 없이도 소속 관계를 전달해야 한다. 색상은 이 구조를 보조하는 역할이다.

### 5.3 색상 적용 방식

상위 그룹별로 다음 세 토큰을 한 묶음으로 사용한다.

```css
--category-<분류-id>-fg
--category-<분류-id>-border
--category-<분류-id>-muted
```

- `fg`: 상위 그룹명, 펼침 제어 텍스트·아이콘, 하위 칩의 텍스트와 테두리
- `border`: 상위 그룹 블록과 하위 컨테이너의 경계
- `muted`: 하위 컨테이너와 칩의 약한 배경

현재 시안에서 고정한 예시는 `프론트엔드`(파랑), `API 연동`(보라), `서비스 도메인`(주황)이다. 실제 구현 전에는 전체 상위 분류에 같은 토큰 체계를 정의하고, 라이트·다크 테마의 대비를 함께 확인한다. 컴포넌트 CSS에는 임의의 HEX 값을 직접 추가하지 않고 `src/styles/tokens.css`의 토큰만 사용한다.

## 6. 구현 대상과 변경 방식

| 대상 | 변경 내용 |
| --- | --- |
| `src/styles/tokens.css` | 모든 상위 분류의 `fg`, `border`, `muted` 토큰을 라이트·다크 테마별로 정의한다. |
| `src/components/RepositoryCard.tsx` | 상위 그룹별 블록을 만들고, 해당 상위 그룹에 연결된 하위 그룹만 계산해 독립적인 펼침 상태와 함께 렌더링한다. 상위 그룹 필터 버튼과 펼침 버튼을 분리하고 적절한 `aria-expanded`, `aria-controls`를 제공한다. |
| `src/styles/components.css` | 기존 카드·칩·포커스·반응형 패턴을 재사용하여 상위 그룹 블록, 펼침 제어, 하위 그룹 컨테이너를 스타일링한다. |
| `tests/` | 상위 그룹별 하위 그룹 분리, 기본 접힘, 독립 펼침, 상위·하위 그룹 필터 클릭 동작을 검증하는 테스트를 추가하거나 갱신한다. |

상위 그룹과 하위 그룹의 연결은 이미 정의된 그룹 데이터의 관계를 사용한다. 이 시각 계층 작업을 위해 `groups.json`의 명명 규칙이나 데이터 자체를 다시 바꾸지 않는다.

## 7. 구현 순서

1. 전체 상위 분류에 대한 색상 토큰 표와 라이트·다크 값을 확정한다.
2. 카드에서 상위 그룹별 하위 그룹 목록을 계산하는 방식을 정리한다.
3. 상위 그룹별 독립 펼침 상태와 접근성 속성을 구현한다.
4. 두 HTML 시안을 기준으로 그룹 블록과 하위 컨테이너 스타일을 적용한다.
5. 그룹 필터, 키보드 포커스, 반응형 레이아웃, 긴 한글·저장소명 조건을 검증한다.

## 8. 완료 기준

- 접힌 카드에서 상위 그룹명과 각 그룹의 하위 개수를 확인할 수 있다.
- 펼친 카드에서 모든 하위 그룹의 상위 소속을 즉시 식별할 수 있다.
- 여러 상위 그룹을 동시에 펼쳐도 각 하위 그룹은 원래 상위 그룹 블록 안에만 표시된다.
- 상위 그룹과 하위 그룹을 각각 클릭했을 때 기존 그룹 필터 동작이 유지된다.
- 현재 카드에 있는 별 수, 포크 수, 브랜치 수, 마지막 수정일, 언어 비율, README 영역은 추가·삭제·재배치하지 않는다.
- 1121px 이상 3열, 768~1120px 2열, 767px 이하 1열과 최소 320px 화면에서 카드 레이아웃이 유지된다.
- 라이트·다크 테마, 키보드 포커스, `prefers-reduced-motion` 조건에서 디자인 규칙을 충족한다.

## 9. 이번 시각 계층 작업에서 제외하는 범위

- 그룹명 공통화와 상위·하위 그룹 데이터 분류 자체의 재논의
- README 펼침 시 스크롤 위치와 `<br>` 노출 문제의 구현
- 현재 카드에 없는 커밋, PR, 기여자, 이슈, 기본 브랜치 등의 메타데이터 추가
- Git 커밋, 푸시, Pull Request 생성 또는 병합
