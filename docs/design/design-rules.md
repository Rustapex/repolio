# Repolio 디자인 규칙

> 이 문서는 Repolio UI의 유지보수 기준이다. 새 기능과 UI 변경은 이 규칙을 기본값으로 삼으며, 기존 패턴을 정당한 이유 없이 바꾸지 않는다.

## 1. 목적과 적용 범위

- 저장소 탐색에 필요한 정보의 가독성과 비교 가능성을 우선한다.
- GitHub Primer에서 영감을 받은 절제된 인터페이스를 유지한다. Primer의 구현물을 복사하거나 프로젝트 고유 스타일을 무분별하게 늘리지 않는다.
- 라이트·다크 테마, 데스크톱·모바일 화면, 키보드 사용 환경에서 같은 기능과 정보 위계를 제공한다.
- 이 문서는 제품 기능의 구현 계획이나 변경 이력용 문서가 아니다. 디자인 원칙, 허용된 패턴, 변경 기준만 기록한다.

## 2. 디자인 시스템의 기준

### 토큰을 유일한 기본값으로 사용한다

- 색상, 간격, 모서리, 그림자, 전환 효과는 `src/styles/tokens.css`의 CSS 사용자 정의 속성을 우선 사용한다.
- 새 일반 UI에 임의의 HEX 색상, 픽셀 간격, 모서리 값을 직접 추가하지 않는다. 언어 비율 막대처럼 데이터 자체를 표현하는 색상만 예외로 한다.
- 테마별 값은 컴포넌트 규칙이 아닌 토큰에서 관리한다. 새 테마 대응이 필요하면 라이트·다크 값을 함께 정의한다.
- 현재 간격 단위는 4px 기반(`--space-1`부터 `--space-12`), 모서리는 `6px`, `10px`, `16px`, pill이다. 새 컴포넌트는 이 값 중 하나를 사용한다.

### 타이포그래피와 콘텐츠 표시를 일관되게 유지한다

- 기본 글꼴은 `--font-sans`를 사용한다. 한글 본문은 `word-break: keep-all`을 유지한다.
- 저장소 이름, URL, 코드처럼 길이를 예측할 수 없는 값에는 `overflow-wrap: anywhere`를 적용한다.
- 본문 텍스트는 일반적으로 `--fg-muted`, 핵심 제목과 조작 요소는 `--fg`, 보조 정보는 `--fg-subtle`을 사용해 위계를 만든다.
- 강조 색상은 링크·핵심 상태·주요 조작에 한정하고 `--accent` 계열을 사용한다. 색만으로 상태나 의미를 전달하지 않는다.

### 공통 레이아웃을 재사용한다

- 페이지 콘텐츠는 `.page-shell`을 사용하고 `--page-width`를 넘기지 않는다.
- 콘텐츠 영역은 배경, 테두리, 간격으로만 구분한다. 불필요한 카드 중첩, 과도한 그림자, 장식성 그라데이션 추가를 피한다.
- 기본 배경은 `--canvas`, 표면은 `--canvas-subtle`, 구분된 내부 영역은 `--canvas-inset`을 사용한다.

## 3. 공통 컴포넌트 패턴

### 헤더와 소개 영역

- 헤더는 브랜드, 동기화 상태, 외부 링크, 테마 전환을 한 행에 유지한다.
- 소개 영역은 eyebrow, 큰 제목, 짧은 설명 순서의 위계를 유지한다. 큰 제목은 기능 설명보다 서비스 정체성에 사용한다.
- 헤더 장식은 현재의 은은한 glow와 원형 윤곽 수준으로 제한하며 콘텐츠 가독성을 방해하지 않는다.

### 검색과 필터

- 검색창은 가장 넓은 제어 요소로 두고, 나머지 필터는 같은 높이와 테두리 스타일을 사용한다.
- 초기화 동작은 `text-button` 패턴을 사용한다. 필터마다 독자적인 버튼 스타일을 만들지 않는다.
- 입력과 선택 요소에는 키보드로 명확히 식별 가능한 focus 상태를 제공한다.

### 저장소 카드

- 카드에는 `repository-card`의 테두리, `--radius-lg`, 표면색, 그림자 규칙을 사용한다.
- 카드의 정보 순서는 상태 배지 → 이름과 외부 링크 → 설명 → 그룹 → 메타데이터 → 언어 정보 → README 미리보기로 유지한다.
- 카드 전체의 높이를 맞추지 않는다. 설명의 최소 높이와 README 미리보기의 제한 높이만 사용해 목록의 읽기 흐름을 안정시킨다.
- public, fork, archived 상태는 badge 패턴을, 사용자 분류는 group chip 패턴을 사용한다. 새 상태는 의미와 대비가 분명한 기존 패턴의 확장으로 추가한다.

### README 미리보기

- README는 카드 내부의 보조 정보다. 기본 상태에서는 높이 제한과 페이드 처리를 유지하고, 사용자가 요청할 때만 확장한다.
- 코드 블록과 넓은 표는 줄바꿈으로 내용을 훼손하지 말고 가로 스크롤을 허용한다.
- README가 없거나 읽을 수 없는 경우에도 카드 구조를 유지하고, 중립적인 빈 상태를 표시한다.

### 버튼과 상태 표현

- 아이콘 단독 조작은 `icon-button` 패턴을 사용하고 목적을 설명하는 `aria-label`을 제공한다.
- 텍스트 링크와 버튼의 hover는 색상·테두리처럼 가벼운 피드백으로 표현한다. 레이아웃 이동이나 큰 확대 효과는 사용하지 않는다.
- 성공, 경고, 오류 상태는 기존 의미 토큰을 사용하고, 텍스트 또는 아이콘으로도 상태를 알 수 있게 한다.

## 4. 반응형 규칙

| 화면 너비 | 저장소 목록 | 필터 | 유지해야 할 원칙 |
| --- | --- | --- | --- |
| 1121px 이상 | 3열 | 검색 + 보조 필터 한 행 | 넓은 화면에서도 콘텐츠 폭을 제한한다. |
| 768px–1120px | 2열 | 두 행까지 허용 | 카드와 필터의 최소 폭을 보장한다. |
| 767px 이하 | 1열 | 가로 스크롤 | 검색을 우선하고 보조 필터를 억지로 축소하지 않는다. |

- 모바일의 페이지 여백, 헤더 높이, 카드 내부 여백은 기존 모바일 규칙을 따른다.
- 최소 화면 폭 320px을 지원한다.
- 새 breakpoint를 추가하기 전에 1120px과 767px 기준에서 해결할 수 있는지 검토한다.

## 5. 테마와 접근성

- 라이트·다크 테마에서 모든 표면, 본문, 보조 텍스트, 테두리, 포커스, 강조색이 읽혀야 한다.
- 테마 전환은 사용자의 선택을 유지하며, 전환 버튼의 현재 상태와 다음 동작을 보조 기술에 전달한다.
- `:focus-visible` 윤곽선과 `prefers-reduced-motion` 대응을 제거하거나 약화하지 않는다.
- 의미 있는 이미지에는 대체 텍스트를 제공하고, 장식 요소는 보조 기술에서 제외한다.
- 명시적 레이블이 화면에 없더라도 입력 요소와 아이콘 버튼에는 접근 가능한 이름이 있어야 한다.

## 6. 새 UI를 추가하거나 기존 UI를 변경할 때

1. 먼저 Header, RepositoryFilters, RepositoryCard, ReadmePreview 및 기존 스타일에서 재사용할 패턴이 있는지 확인한다.
2. 기존 토큰과 클래스 패턴으로 해결할 수 있다면 새 변형을 만들지 않는다.
3. 새 패턴이 필요하면 라이트·다크 테마, 1120px/767px 반응형 전환, 키보드 focus, 긴 한글·URL·빈 데이터 상태를 함께 확인한다.
4. 토큰, 반응형 기준, 정보 위계, 공통 패턴을 변경하는 경우 이 문서도 같은 변경에서 갱신하고 이유를 명시한다.
5. 구현 계획 문서에는 일정과 기능 범위를, 이 문서에는 장기적으로 지켜야 할 디자인 규칙만 기록한다.
